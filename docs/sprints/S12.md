# S12 — Navigation, editing and action clarity

Requested 2026-11-01. Preserve PraisePoint's Figtree, teal palette and Liquid Glass identity. Local refinement and QA were approved first; the user subsequently authorized publication to the existing GitHub repository and Firebase Hosting site.

## Accepted behavior

- Move workspace selection into the sticky top bar, remove duplicate account initials there, and make the dropdown arrow a working target.
- Desktop rail: collapsed CCF logo reveals a menu on hover/focus; expanded sidebar has its collapse control in the brand row. Sign out is visible only while expanded (always available in the mobile drawer).
- Consistent button states, action hierarchy, wrapping and spacing throughout existing screens.
- New song starts with its details. Save labels reflect confirmed successful writes and reset when edited; failed writes never show success.
- Presentations owns creation. Templates becomes a gallery of free background sources. User accepted external previews plus download/import; no direct streaming in slides or automatic Supabase uploads.
- Text selects on click, edits on double-click or keyboard activation, and moves only through its move handle. Images retain drag behavior.
- Remove the oversized media storage panel; retain compact, useful capacity information.

## Sequence and evidence

1. Reproduce navigation/song/text defects with focused tests and inspect existing visuals.
2. Correct shell and editing behavior; standardize actions and save feedback.
3. Resolve background delivery with user and implement the gallery.
4. Run unit/type/lint/build checks and browser flows at desktop, tablet and mobile widths, including keyboard, scrolling, hover, error and disabled states.
5. Inspect rendered screenshots, apply polish, run the Impeccable detector once on final changed UI, and document audit evidence and limits.

No database/schema change or provider subscription is planned. Browser API fixtures keep church records untouched. Physical phone/projector verification remains separate.

## Root causes and implemented corrections

- The workspace chevron was outside the native select hit area. The select now covers the 44px arrow target in the header, with its accessible label intact.
- New song initialized lyric review to open. It now starts with song details; volunteers explicitly open lyrics and review breaks before saving.
- Text hitboxes started whole-box movement on pointer down. Text now selects without dragging; double-click/keyboard activation enters native text editing, while the dedicated handle retains movement.
- The selection overlay used `pointer-events: none`, inherited by its textarea and move handle. Both now explicitly receive pointer input. Real browser hit testing and drag geometry verify the correction.
- Filtered glass ancestors constrained fixed-position preview. The preview now uses a body portal. Fullscreen cleanup checks actual disconnection after the React effect cycle, preserving development-mode fullscreen and exiting on real unmount.
- Three save surfaces now reflect persisted state; failures retain the draft and save/retry action. Shared action variants and hover treatment apply across the app.

Background sources, audit findings, verification results and limits are recorded in `docs/evidence/S12-audit.md`.
