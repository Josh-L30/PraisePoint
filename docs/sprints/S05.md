# S05: Song masters and service plans

Status: Done, verified 2026-10-27. Base ae19e1df5bd7e1189734e1b70b250fab50ab7202. No deployment.

Implemented: searchable, paginated song library with explicit master saves, writer/source/usage notes, typed or pasted lyrics, font-ready break review and editable per-slide words. Blank stanza boundaries and repeated choruses are retained; splitting happens only at existing lines, four lines per slide. Long lines produce width warnings without truncation. Existing service copies remain independent when a master changes.

Service plans have a title, optional calendar date, stable ordered items, revisioned atomic saves, native reorder buttons, existing-presentation selection and reviewed song-to-service copies. Adding a song checks both reviewed revisions under the same database lock before creating and appending its deck. Existing presentations are reused explicitly; make a separate presentation copy when independent edits are needed. Unsaved changes and pending writes guard navigation/sign-out. Failed saves retain the current form; reload discards only after confirmation.

Snapshot construction runs in the database under the document/workspace locks. It freezes the saved service order and deck contents, computes a SHA-256 source-revision digest, and records service-item sections for the upcoming presenter. Repeated decks get deterministic, distinct occurrence slide/element UUIDs. The client validates section coverage, unique identities, sizes and response identity, then freezes the returned snapshot. The online review uses the existing fixed-layout renderer. It makes no offline-readiness or live-projector claim.

Migration 20261027025927 adds songs, service plans/items, composite workspace-bound foreign keys and source-song provenance. Authenticated members read through RLS and write through validated RPCs; raw writes are denied. Owners delete shared song masters and services; creator/owner deck deletion remains as before. Referenced items return bounded dependency descriptions; deleting a service removes only its order, retaining presentations and masters. Serialized song/service metadata shares existing 25 MiB/workspace and 100 MiB/application document budgets. Bounds: 200 lyric slides/song, 200,000 song characters, 100 service items, 2,000 snapshot slides, 16 MiB snapshot. These are application limits, not provider disk guarantees.
