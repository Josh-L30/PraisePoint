# S06: Persistent media and private still images

Status: Done, verified 2026-10-28. Base 2fe98a04021d53f0fabfdc45053306012d28f76c. Frontend remains local; authenticated media-upload Edge Function v2 is deployed to the existing Free Supabase project. No paid service or public website release.

Volunteers can import local stills/videos or upload private JPEG/PNG/WebP stills, verify files, reselect missing originals, copy media independently between authorized workspaces, and remove unreferenced media as an owner. The media library shows actual used/reserved capacity and unfinished operations. Retry retains the original File and media identity. Local MP4/WebM are limited to 128 MiB per file; MP4/H.264/AAC is the recommended rehearsal format, with actual browser decoding required. Local files remain on that browser/profile and are not shared by a catalog entry.

The editor supports image placement, resizing, contain/cover fit, media backgrounds and standalone video selection. Saved service review and full-window preview use the same profile-bound resolver. Thumbnails keep videos paused; the active canvas can animate backgrounds. Standalone video is muted/paused here: presenter transport and audience-only audio belong to S07. Metadata snapshots strictly validate all referenced media IDs, types and workspaces.

Local persistence uses version 2 of gather-device IndexedDB, preserving the existing profile marker. Bytes are size/MIME/hash checked before storage and on resolution, with native full-image or first/ending-video decode before acceptance. Full-file hashing is serialized; overlapping resolutions of the same asset share a read. Object URLs are released on unmount and profile purge. Sign-out atomically removes that profile's local files and revokes its URLs. A catalog failure retains the original for retry; quota denial never reports success. This is media persistence, not complete offline service preparation (S08).

Server contracts: validated media_assets and derived deck_media with composite workspace foreign keys; private image counters and 15-minute reservations; 5 MiB/cloud still, 50 MiB/workspace, 500 MiB/application, 30 new uploads/hour/actor. Private gather-images bucket denies direct client writes. An authenticated proxy verifies the server-issued Google identity, actual bounded bytes/hash/type/full decode and exact reserved path; service-role finalization checks stored size/MIME before making an asset readable. No elevated key or Google credential enters the frontend. Cloud copies reserve their own destination capacity and keys; local copies preserve verified bytes under new destination IDs. Presentation copies require complete exact media mappings and the reviewed source revision. Dependency-aware deletion removes object bytes before releasing used quota.

A service-only single-writer claim prevents overlapping retries from starting a second write. Busy retries can only verify an existing complete object and finalize. Unclaimed/legacy aborts cannot interrupt a live writer, and started failures retain reserved capacity until expiry. First claim requires at least three minutes remaining; all upstream calls for one proxy request share a 90-second deadline. Expired cleanup removes objects before releasing capacity; late inserts fail the reservation/state guard. The Storage authorization probe uses contentLength, while final metadata uses size; both are checked. Active finalization is idempotent and a lost response cannot cause cleanup to delete a readable image.
