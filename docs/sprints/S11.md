## Acceptance

1. Smaller, balanced login card and left illustration at laptop and phone sizes. Retain Figtree, teal palette and restrained glass.
2. Rename all user-visible Gather branding to PraisePoint. Use the real CCF logo from its official website, locally cached and tinted with our palette. Keep internal storage/cache/database identifiers compatible; changing brand must not lose prepared copies.
3. Compact desktop navigation with bottom controls visible at ordinary laptop heights; responsive scroll fallback for short/mobile screens. Remove slow layout animation and excessive blur. Preserve keyboard focus and accessible labels when collapsed.
4. Only church owners may permanently delete their church workspace and its presentations, song masters, service plans, memberships/invitations and media metadata/cloud images. Personal work remains separate. Require centered destructive confirmation naming the workspace and its consequences. Use resumable server-side cleanup: verify owner, refuse outstanding upload leases, freeze writes, remove scoped content, delete stored cloud bytes before releasing their quota, then remove the workspace. Failed cleanup retains a resumable deletion state; never falsely report success. Local prepared copies on other disconnected devices cannot be remotely erased.
5. Editor imports a song's reviewed slide breaks from Song library into independent presentation slides without retyping or changing the song master. Allow review before applying.
6. All app confirmation/creation/edit dialogs use centered top-layer modal presentation, short entrance motion, focus containment/restoration, Escape/Cancel and disabled dismissal during a write. Browser-owned reload/close warnings remain browser-controlled.
7. Give service metadata import and the empty-service state clear vertical spacing.
8. Replace native file-input chrome with accessible icon upload/relink controls, selected filenames and appropriate hints, retaining the real native chooser.
9. Edit/select text directly on canvas and move/resize boxes using a clear dedicated move handle; preserve keyboard alternatives, undo/redo and exact words/styles.
10. Preview has an accessible Back icon and real browser fullscreen where supported, graceful rejection, intact 1920×1080 geometry and background-matched unused space. Never crop or stretch slide content to fill an incompatible aspect ratio.
11. Media deletion opens a centered Confirm Deletion modal, removes actual cloud bytes and database metadata through the existing authorized backend, and only then reclaims capacity. Referenced media remains blocked until released.
12. QA covers actual rendered desktop/mobile layouts, overflow, modal centering/focus, native editor gestures/selection, slide geometry, permission/cancellation/failure cases and media quota/storage ordering. Viewport emulation is not hardware certification.
13. Deployment is prepared/reviewable after verification; do not delete existing live workspaces or church files as QA. No new paid service or dependency.

## Implementation decisions

Reuse existing router, media cleanup pipeline, local storage identities and installed lucide icons. Centered dialogs use native dialog/top-layer with React portals. Account-change guards become asynchronous so custom confirmation does not bypass dirty/save/update protection. Workspace deletion is staged and retryable because database transactions cannot atomically delete Storage bytes. Pending uploads must finish/expire and be reclaimed first. Source inspection found media CORS currently allows localhost only; add the exact two owned Firebase origins and verify denied foreign origins.
