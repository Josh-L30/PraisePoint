# S03: Slide templates and safe saves

Status: Done, verified 2026-10-27. Base: 16fcaabb3f0057186855b4bfe3bdaab06ed90ab4. No deployment.

Scope: five editable template categories, fixed 1920×1080 shared renderer, validated cloud documents, listing/copy/delete, revision conflicts, retained drafts and navigation protection. Freeform positioning follows in S04; real media persistence follows in S06.

Implemented: five editable templates; manual Scripture passage/reference/translation fields; presentation listing with 24-item pages; explicit creation, copying and deletion; text/style/background changes; slide addition/duplication/deletion; profile-scoped drafts; revision conflicts with reload or draft-copy recovery; navigation/sign-out guards; and full-window preview using the shared fixed-stage renderer. Freeform controls, media, service plans, operator/audience presentation and offline readiness remain later work.

Validation: strict versioned documents, unique/canonical UUIDs, finite geometry, permitted fonts/colors, 200 slides/deck, 100 elements/slide, 20,000 characters/text, 2 MiB/document. Text stays literal; words and line breaks are preserved. Stage layout is fixed at 1920×1080 and scales uniformly. Figtree must load before output. Text uses white-space:pre to prevent automatic viewport wrapping; overflow is reported, not silently shortened.

Database: migration 20261026180211_slide_decks applied once. Read RLS requires current membership; raw writes are denied. Private transactional APIs validate documents, check membership under workspace locks, compare revisions, enforce actor writes and account for document storage. Members edit shared content; only its creator or the workspace owner can delete a deck. Explicit cross-workspace copies check both memberships. Media references are rejected until S06 supplies a workspace media catalog.

Pilot document budgets: 25 MiB/workspace and 100 MiB across the application, measured as serialized server JSON, plus the 2 MiB/document limit and 120 content writes/minute/actor. A shared locked accounting row serializes capacity changes. These are app budgets with provider headroom, not a guarantee of physical disk capacity; capacity failures keep the draft. The server’s JSON serialization includes whitespace, so its byte count may be slightly larger than the compact client serialization.

Full-window preview is an online protected preview, not the later two-window presenter.
