# Back up and move a service

1. On the source laptop, save every change, open the service and choose Review service slides → Download service metadata. A prepared service can also download its frozen saved version from Prepared services, even while disconnected. The download is named gather-service-metadata.json.
2. Keep that JSON together with the exact original image/video files in your own backup folder or USB drive. The JSON contains titles, words, layout, ordering and media fingerprints. It includes no media bytes, Google tokens, source workspace access or signed download links. Handle the words and filenames as church content when sharing it.
3. On the destination laptop, open the same production app origin online in current desktop Chrome/Edge. Sign in, select the intended personal/church workspace, open Service plans → Import service metadata and choose the JSON. Review the title, counts and destination before Import independent service. This creates new records; existing services/song masters are unchanged. A lost response can mean the import succeeded: check the library before importing again.
4. Open Media library. Every imported image/video is an independent local original; source cloud images are not automatically downloaded or granted to another workspace. Reselect exact original beside each imported file. Name alone is insufficient: the app checks type, byte count, SHA256 and native decode. A different file requires importing it separately and updating the slide references.
5. Review the imported service, prepare it for offline use, then open Prepared services and Verify prepared copy. Close/reopen the browser disconnected and rehearse the projector output. First setup/sign-in/import require internet; an intact prepared service does not.

Browser data is tied to the exact origin and browser profile. Changing ports, using Incognito, clearing site data or signing out can remove access. JSON is the portable metadata backup; prepared browser caches are not a backup file and do not replace original-media backups. Store more than one copy of the originals and retain them after relinking. A JSON import does not include reusable song masters, service date or source ownership: it preserves the frozen presentation content and order, and the date can be entered on the new plan.

Unsupported future formats and damaged/oversize files are refused before import. Failed server validation or capacity checks roll back the entire import. A failed offline refresh keeps the previous complete prepared version. Physical USB/second-laptop and actual projector/speaker rehearsal remain the operator's release acceptance checks.
